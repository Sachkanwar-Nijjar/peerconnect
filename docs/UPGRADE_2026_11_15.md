## Public deployment
Dockerfile and .env.production.example prepare deployment to a Node-compatible host and PostgreSQL service. No hosting account, domain, SMTP credentials or paid plan has been provisioned. Public hosting and real email delivery remain unverified and require those resources. Do not use local demo database credentials or accounts for a public launch. Configure TLS, secrets, email sender verification, managed backups/restore and monitoring. Run migrations and seed-learning on deployment. The container command does this automatically.

Auth recovery has 30-minute single-use digested tokens and revokes sessions. Development delivery is explicitly local-only; production needs SMTP. Existing auth rate limiting is per process; deploy a shared rate limiter before a multi-instance public launch. Guidance request daily throttling is database-backed. Add block/report flows for mentoring before a broad public rollout; existing community moderation does not yet cover private guidance.

## Opening locally
Use the updated complete Windows folder's OPEN-WEBSITE.cmd. Keep its window open, then open the printed address in Chrome. Source folder can use OPEN-PEERCONNECT.cmd (Node required). Desktop copies and old ZIPs are not automatically updated.
